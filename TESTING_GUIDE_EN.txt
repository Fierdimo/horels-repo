IMPORTANT CLARIFICATION: CREDIT SYSTEM
═════════════════════════════════════════════════════════════════════════════
The credits system in this platform is FLEXIBLE and CONFIGURABLE:

- Conversion rates are NOT hardcoded (no fixed "7 credits per week" rule)
- Admin can configure variables that determine credit values
- Each property/week type can have different valuation rules
- Owners see ESTIMATED CREDITS before confirming conversion
- The actual conversion values depend on admin configuration in backend
- This allows the platform to adjust valuation as needed for business logic

For testing purposes: Verify that estimated credits are shown and conversion
works - the actual numbers will depend on how admin has configured the system.

   - Find swap requests from other owners
   - Filter by destination country

   - View detailed swap opportunities

   - Filter by week dates and properties

B) MY REQUESTS
   - All swap requests created by this owner
   - Track request status (pending, matched, approved, rejected)
   - View who responded to their requests
   - Accept/reject counter-offers
   - Cancel pending requests if needed

C) CREATE SWAP
   - Select a week to offer
   - Search for compatible weeks from other owners
   - Specify desired dates and property (optional)
   - Add notes or preferences
   - Submit request for staff review

COMPLETE SWAP WORKFLOW:

Step 1: Owner Creates Request
- Select their week to offer
- View compatible weeks from other owners
- Choose to target specific week or leave open
- Add notes about preferences
- API: POST /owner/swaps
- Status becomes: "pending"

Step 2: Staff Reviews Request
- Staff sees request in pending queue
- Checks compatibility and dates
- Verifies no conflicts
- Reviews peak date restrictions
- Approves or rejects with reason

Step 3: Other Owner Responds (if approved)
- Receives notification of match
- Reviews offered week details
- Decides to accept or reject
- Can add conditions or notes

Step 4: Second Owner Accepts
- Both parties confirmed
- Status changes to "matched"
- Owner sees payment amount due (€10 platform fee)

Step 5: Payment Processing
- Owner completes Stripe payment
- Receives payment confirmation email
- Platform processes payment

Step 6: Exchange Completed
- Weeks are transferred
- Both owners receive confirmation
- Week status updated in system
- New week appears in their account

TESTING URLS:
- GET /owner/swaps - Get all owner's swap requests
- GET /owner/swaps/browse/available - Browse other owners' swaps
- GET /owner/swaps/compatible-weeks/:weekId - Find compatible weeks
- POST /owner/swaps - Create new swap request
- GET /owner/swaps/:swapId - View swap details
- POST /owner/swaps/:swapId/accept - Accept swap request
- POST /owner/swaps/:swapId/reject - Reject swap request

SWAP STATUSES:
- pending: Waiting for staff review
- matched: Staff approved, waiting for other owner response
- approved: Both owners agreed, ready for payment
- completed: Week exchanged and payment processed
- rejected: Staff or other owner rejected
- cancelled: Owner cancelled their request

NOTIFICATIONS SENT:

5. CREDITS SYSTEM
================================================================================

CURRENT STATUS: [IMPLEMENTED] FULLY IMPLEMENTED 

MAIN PAGE: /owner/credits

WHAT ARE CREDITS?
- Credits are awarded when owners convert assigned weeks to credits
- Each week conversion amount is calculated using ADMIN-CONFIGURED VALUATION RULES
- Not a fixed "1 credit = 1 night" formula - varies based on week properties
- Credits expire (expiration date shown on dashboard)
- Can be used for any booking in marketplace

CREDIT VALUATION (HOW CONVERSION IS CALCULATED):
The amount of credits received when converting a week is determined by:
- Admin-configured variables in the platform settings
- These variables can include location, seasonality, room type, or other factors
- Each property/week may have different conversion rates
- Owners see ESTIMATED CREDITS before confirming conversion
- The actual value is calculated dynamically based on admin configuration
